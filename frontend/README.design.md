# Figma 디자인 구현 — 이슈 #23

## 실행

```sh
cd frontend
npm ci
npm run dev
```

`http://localhost:5173/design`에서 시작합니다. 다른 프론트엔드 작업과 충돌하지 않도록 기존 `/`의 API 기반 메인 화면과 공통 인증 코드는 보존했습니다. 디자인 전용 라우트는 `src/constants/designRoutes.js`, 진입점은 `src/pages/design/DesignApp.jsx`입니다. 공통 라우터를 바꾸지 않고 `App.jsx`에서 `/design/*`만 연결합니다.

## 시연 범위와 API 연결 지점

- 화면 상태는 별도 Zustand `useDesignStore`의 메모리에 저장되며 새로고침 시 초기화됩니다. 실제 로그인, 카드 결제, 환불, 알림톡 전송, 지도 검색은 수행하지 않습니다.
- Figma 날짜 예시는 2025년 10월로 고정했습니다. 달력은 예시 기준 10월 22일부터, 빈자리 등록은 10월 24일부터 선택할 수 있습니다. 탐색 날짜 칩은 실제 2025년 요일을 표시합니다.
- 예약 흐름: 카드 → 매장·시술 상세 → 할인 빈자리 예약 또는 일반 날짜·시간 선택 → 5분 임시 확보 → 두 가지 필수 동의 → 모의 결제 → 예약 결과 → 내 예약. 결제 실패·확보 만료·검색 결과 없음·로딩·조회 오류를 직접 시연할 수 있습니다.
- 상세 화면에서 빈자리를 예약하면 카드의 할인 가격·시술 시간과 20% 예약금을 유지합니다. 일반 예약은 원본의 90분·정상가·20% 예약금 정책을 사용합니다.
- 취소 시연 기준 시각은 원본 내 예약 화면의 시술 40분 전(2025-10-24 14:50)으로 고정합니다. 환불액은 확정 정책(이용 2일 전까지 20,000원 / 1일 전 10,000원 / 당일 0원, 납부 예약금 한도)으로 계산하고, 내 예약 화면에서 예약금결제 상태(결제 완료 → 환불 처리 중 → 환불 완료·부분 환불)와 결제·환불 이력을 보여줍니다. 실제 서비스에서는 서버의 현재 시각·예약 상태·정책을 기준으로 계산해야 합니다.
- 사장님 메뉴 수정은 이미 확정된 예약 가격에 소급 적용되지 않습니다. 확정·임시 확보 슬롯의 판매 상태 변경은 막고, 새 슬롯의 시간 겹침을 검사합니다.
- 고객 탐색 메뉴는 ‘빈자리 찾기’로 통합했습니다. 전체는 정상가·할인가를 모두 표시하고, 타임세일은 오늘 시작하는 할인 자리만 표시합니다. 목록·지도 전환 시 검색 조건을 유지하며 같은 데이터와 상세 링크를 사용합니다. 지도는 실제 위치 검색이 없는 예시입니다. 기존 `/design/explore`, `/design/explore-classic` 주소는 통합 화면의 지도 보기로 이동합니다.
- 실제 API 연결 시 기존 `axiosInstance`를 재사용하고 `컴포넌트 → store 액션 → api 모듈 → axiosInstance` 흐름으로 연결해야 합니다. 디자인 store를 인증 store에 합치지 않습니다.

## 추가 제공된 원본 화면

Figma MCP 호출 한도로 조회하지 못했던 네 화면은 사용자가 2026-10-22에 제공한 선명한 PNG를 기준으로 추가 구현했습니다. 신규 이미지를 화면 전체의 배경으로 넣지 않고 React 컴포넌트와 CSS로 작성했습니다. 별도로 제공되지 않은 개별 사진·아이콘은 기존 프로젝트 에셋과 텍스트/CSS 표현을 재사용하므로 원본과 세부 차이가 있습니다.

프로필 수정, 찜 전환, 빈 목록 시연, 알림 조건 설정, 결과 화면의 성공/실패/만료 미리보기와 독립 빈자리 등록 페이지를 제공합니다. 새 슬롯은 비활성 시술·기간·운영 시간·30분 단위·기존 예약 및 슬롯과의 충돌을 같은 검증 함수로 검사합니다. 원본 등록 예시의 16:30은 기존 데모의 17:00 슬롯과 겹치므로, 초기값은 충돌이 없는 14:00으로 설정했습니다. 원본의 16:30 추천 버튼을 누르면 충돌 안내가 표시됩니다.

기존 예시 예약(네일, 2025-10-24 15:30)은 중복 예약이 차단됩니다. 할인 예약 흐름을 새로 시연하려면 헤어 카드의 17:00 빈자리를 사용하거나 일반 예약에서 다른 날짜를 선택합니다.

기존 메인/API 화면을 기본 디자인으로 전환하는 작업과 실제 API 통합은 포함하지 않았습니다. `App.jsx`의 진입 경로 연결은 파트장 리뷰 대상입니다.

## 검증

- `npm run lint` — 오류·경고 0
- `npm run build` — 성공
- Edge 헤드리스 브라우저에서 1280px / 390px 화면, 원본 이미지 로딩 및 가로 넘침 확인
- 필터 초기화, 오류 재시도, 약관 동의 검증, 모의 결제 실패·성공, 예약 취소, 확보 만료, 시술 생성·비활성화, 빈자리 충돌 검사 확인

검증용 브라우저 자동화는 로컬 번들 Playwright를 사용했으며 프로젝트 의존성은 추가하지 않았습니다.
