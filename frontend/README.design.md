# Figma 디자인 구현 — 이슈 #23

## 실행

```sh
cd frontend
npm ci
npm run dev
```

`http://localhost:5173/design`에서 시작합니다. 다른 프론트엔드 작업과 충돌하지 않도록 기존 `/`의 API 기반 메인 화면과 공통 인증 코드는 보존했습니다. 디자인 전용 라우트는 `src/constants/designRoutes.js`, 진입점은 `src/pages/design/DesignApp.jsx`입니다. 공통 라우터를 바꾸지 않고 `App.jsx`에서 `/design/*`만 연결합니다.

## 시연 범위와 API 연결 지점

- 화면 상태는 별도 Zustand `useDesignStore`의 메모리에 저장되며 새로고침 시 초기화됩니다. 실제 로그인, 카드 결제, 환불, 알림톡 전송, 지도 검색은 수행하지 않습니다.
- Figma 날짜 예시는 2025년 10월로 고정했습니다. 달력은 예시 기준 10월 22일부터, 빈자리 등록은 10월 24일부터 선택할 수 있습니다. 날짜 칩의 요일 표기는 원본 디자인을 따릅니다.
- 예약 흐름: 카드 → 날짜·시간 선택 → 5분 임시 확보 → 두 가지 필수 동의 → 모의 결제 → 내 예약. 결제 실패·확보 만료·검색 결과 없음·로딩·조회 오류를 직접 시연할 수 있습니다.
- 일반 예약은 원본의 90분·정상가·20% 예약금 정책을 사용합니다. 타임세일 카드 가격은 별도 할인 예시이며 일반 예약으로 넘어가면 정상가를 명시합니다.
- 취소 시연은 원본 내 예약 화면의 시술 40분 전 구간으로 고정하며 예약금의 50%를 모의 환불합니다. 실제 서비스에서는 서버의 현재 시각·예약 상태·정책을 기준으로 계산해야 합니다.
- 사장님 메뉴 수정은 이미 확정된 예약 가격에 소급 적용되지 않습니다. 확정·임시 확보 슬롯의 판매 상태 변경은 막고, 새 슬롯의 시간 겹침을 검사합니다.
- 탐색 대체 시안의 매장 및 가격은 원본 예시입니다. 예약 링크는 연결된 기본 시술의 일반 예약 화면으로 이동하므로 다음 화면에서 기본 매장·가격을 확인할 수 있습니다.
- 실제 API 연결 시 기존 `axiosInstance`를 재사용하고 `컴포넌트 → store 액션 → api 모듈 → axiosInstance` 흐름으로 연결해야 합니다. 디자인 store를 인증 store에 합치지 않습니다.

## 남은 원본 화면

Figma MCP의 Starter 플랜 호출 한도로 `8:2`, `8:7`, `18:3220`, `32:467`의 상세 디자인을 가져오지 못했습니다. 이 네 노드의 개별 화면 구현은 미완료입니다. 확보한 화면은 위 표에 한정하며 원본 전체 구현이 완료된 것은 아닙니다.

기존 메인/API 화면을 기본 디자인으로 전환하는 작업과 실제 API 통합은 포함하지 않았습니다. `App.jsx`의 진입 경로 연결은 파트장 리뷰 대상입니다.

- `npm run lint` — 오류·경고 0
- `npm run build` — 성공
