# 회원 API (UNNIE-149)

고객·관리자 계정(`APP_USER`)의 정보를 다룬다. 매장 계정은 `SHOP` 행에 있어 매장 API(`shops.md`)를 쓴다.

## GET /api/v1/users/me — 내 회원 정보

```json
{
  "success": true,
  "data": {
    "userId": 1,
    "name": "고객일",
    "phone": "010-1111-1111",
    "createdAt": "2026-10-01T09:00:00+09:00"
  },
  "error": null,
  "timestamp": "2026-10-30T23:01:44+09:00"
}
```

| 상황 | 응답 |
|---|---|
| 비로그인 | 401 `COMMON_401` |
| 매장 | 403 `COMMON_403` |
| 회원 행 없음 | 404 `COMMON_404` |

- 현재 사용자 ID·역할·매장 ID만 필요하면 `GET /api/v1/auth/me`를 쓴다.

## POST /api/v1/users/me/withdrawal — 회원 탈퇴

고객만 탈퇴할 수 있다. 회원 행은 지우지 않고 `STATUS`를 `INACTIVE`로 바꾸며, 예약·결제 기록은 매장 정산을 위해 남긴다.

```json
{ "password": "현재 비밀번호" }
```

성공하면 본문 없이 `204`. 프론트는 세션을 지워 바로 로그아웃한다. 탈퇴 전에 받은 토큰은 다음 요청부터 계정 상태 검사(`CustomerLoginStatusChecker`)에 걸려 비로그인(401)이 된다.

탈퇴할 때 함께 처리하는 것:

- 이름을 `탈퇴회원`으로 가린다. 휴대폰 번호는 같은 번호로 다시 가입할 때까지 남겨, 탈퇴 계정으로 로그인하면 `AUTH_003`으로 안내한다
- 사용 중인 알림 구독·찜을 해제한다(`INACTIVE`)
- 받은 알림(`NOTIFICATION_INBOX`)을 지운다
- 아직 보내지 않은 알림 문자(`NOTIFICATION_DISPATCH`의 `PENDING`)를 `SKIPPED`로 끝낸다
- 예약 대기열(번호표)은 서버 메모리에 있어 대기 화면이 순서를 묻지 않으면 곧 빠지므로 따로 지우지 않는다

| 상황 | 응답 |
|---|---|
| 비로그인 | 401 `COMMON_401` |
| 관리자·매장 | 403 `COMMON_403` |
| 비밀번호가 틀림 | 400 `USER_001` |
| 만료 전 결제 대기(`HOLD`), 방문이 끝나지 않은 예약(`CONFIRMED`, 종료 시각 전), 취소 처리 중(`CANCEL_PENDING`) 예약이 있음 | 409 `USER_002` |

- 결제 대기도 막는 이유: 결제 확정은 회원 잠금을 쓰지 않고 `HOLD`에서만 일어난다. 탈퇴 검사 시점에 확정 중이면 아직 `HOLD`, 확정 뒤면 `CONFIRMED`라 어느 쪽이든 막혀, 탈퇴 회원에게 확정 예약이 남지 않는다

### 탈퇴 후 다시 가입

- 탈퇴한 아이디(`LOGIN_ID`)는 다시 쓸 수 없다
- 같은 휴대폰 번호로는 새 아이디로 다시 가입할 수 있다. 가입할 때 탈퇴 계정의 번호를 `WD-{USER_ID}`로 바꿔 `UK_APP_USER_PHONE`을 비운다
- 지난 예약 기록은 탈퇴 계정에 남고 새 계정으로 옮기지 않는다
