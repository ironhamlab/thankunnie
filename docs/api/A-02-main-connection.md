## C와 맞출 임시 연결 계약

현재 dev에는 C 탐색·상세 화면 및 탐색 컨트롤러가 없다. 아래 경로와 추가 필드는 A-02의 임시 계약이며 C 담당자의 기존 구현을 확인한 결과가 아니다.

| 동작 | 대상 | 전달 내용 |
| --- | --- | --- |
| 카드 전체 클릭 | `/items/:id` | 서버가 반환한 양의 정수 ID |
| 오늘/마감 임박 더보기 | `/explore` | A-01 해당 프리셋의 모든 필터와 정렬, page=0 |
| 날짜·정렬 선택 후 ‘조건으로 탐색’ | `/explore` | 선택 날짜의 startDate/endDate, sort, availableOnly=true, page=0, size=6 |

아래 이동 계약은 C 화면 등록 후 연결을 활성화했을 때 적용한다. 현재는 상세·더보기 링크를 노출하지 않고 날짜·정렬 입력 및 탐색 제출을 비활성화하며, 화면에 탐색 준비 중 안내를 표시한다.

상세 경로에는 가격·상태를 넘기지 않는다. C 상세는 ID로 최신 정보를 조회해야 한다. 링크는 React Router Link를 사용해 키보드 이동과 새 탭 열기를 지원한다.

추가한 경로 상수는 `src/constants/routes.js`에 있다. 현재 AppRouter에는 이 경로의 C 화면이 등록되어 있지 않다. 초기 구현의 링크는 NotFound로 연결됐으나 리뷰 수정으로 MAIN_ROUTE_AVAILABILITY.EXPLORE와 ITEM_DETAIL을 false로 두고 링크 노출을 보류했다. 경로를 주소창에 직접 입력하면 여전히 NotFound가 표시된다. C 화면 구현 후 이 상수에 맞춰 등록하거나 실제 경로로 변경하고, 등록 검증 후 각 플래그를 true로 변경해야 한다. 공통 AppRouter를 수정하거나 C 화면을 대신 구현하지 않았다.

### 탐색 쿼리 예시

```text
/explore?availableOnly=true&startDate=2026-10-25&endDate=2026-10-25&sort=CLOSING_ASC&page=0&size=6
/explore?availableOnly=true&closingWithinHours=24&sort=CLOSING_ASC&page=0&size=6
```

선택 날짜가 비어 있으면 날짜 범위를 보내지 않는다. 정렬의 ‘마감 임박순’ 선택은 CLOSING_ASC 정렬만 지정하며 24시간 제한을 자동으로 추가하지 않는다. ‘마감 임박’ 영역의 더보기에는 A-01에 정의된 24시간 제한을 유지한다.

필터는 URLSearchParams로 직렬화한다. 이전 페이지 번호는 전달하지 않고 0으로 초기화한다. 지원 쿼리 외 내부 값은 URL에 넣지 않는다. 조건 선택은 폼에서 하고 탐색 버튼으로 적용한다.

## 카드 표시 계약

기존 A-01의 id, title, startsAt, applicationClosesAt 외에 아래 필드를 C와 협의해야 한다.

| 필드 | 임시 타입 | 표시 |
| --- | --- | --- |
| shopName | string, 선택 | 매장명 |
| imageUrl | string, 선택 | API 제공 이미지 URL. 누락·잘못된 값·이미지 로드 실패 시 이미지 준비 중 표시 |
| price | number, 원화 판매가 | 한국 원화 형식. 0도 유효한 가격 |
| originalPrice | number, 선택 | 판매가보다 높을 때만 취소선 정상가 |
| status | string | 아래 상태명 매핑 |

| 상태 | 화면 표시 |
| --- | --- |
| AVAILABLE | 예약 가능 |
| HELD | 임시 확보 중 |
| BOOKED | 예약 완료 |
| SOLD_OUT | 매진 |
| CLOSED | 마감 |
| CANCELLED | 취소 |

가격 누락·문자열·음수·NaN 등은 ‘가격 확인 필요’, 알 수 없는 상태는 ‘상태 확인 필요’로 표시한다. 일정 파싱 실패도 안내 문구를 표시하며 화면을 깨뜨리지 않는다. 잘못된 ID에는 링크를 생성하지 않는다. 상태만으로 상세 접근을 차단하지 않으며 실제 예약 가능 여부는 C 상세·예약 API가 판단한다.

## 기존 디자인 통합

사용자 요청에 따라 기존 디자인의 design.css 테마, 브랜드, 히어로 배너, 필터 패널, 이미지형 카드와 공통 헤더·푸터를 API 메인에 연결했다. 공통 MainLayout 수정은 사용자가 이번 대화에서 명시적으로 승인했다.

- 메인 목록의 데이터 출처는 기존 useMainStore → itemApi → axiosInstance이며, 응답 순서와 24번의 필수 필드·날짜 검증을 유지한다.
- SERVICES, 고정 시연 날짜, useDesignStore 및 시연용 예약·결제·할인 계산은 API 메인에서 사용하지 않는다.
- 원래 /design 경로와 시연 코드는 그대로 유지한다. API의 숫자 ID를 시연용 문자열 ID에 대응시키지 않는다.
- 원래 디자인의 시술 분야·지역·시간 필터는 C API 계약이 없어 기능처럼 표시하지 않는다. 기존 날짜·정렬 필터와 C 화면 연결 대기 처리를 유지한다.
- 헤더도 실제 등록된 홈·로그인만 연결한다. 시연용 고객 이름·예약 건수·가짜 계정 전환을 가져오지 않는다. 매장 검색은 C 연결 전까지 비활성화한다.
- 이미지가 없을 때 다른 매장의 시연 사진을 임의로 넣지 않는다. API 제공 imageUrl만 사용하고 실패 시 준비 중으로 대체한다.
- 할인율·임박 배지는 임의 계산하지 않고 서버 가격·상태를 표시한다.
