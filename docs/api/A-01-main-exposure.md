## 2. 메인 노출 기준

아직 조회 대상의 실제 도메인이 제공되지 않아 이 문서에서는 이를 `항목(item)`으로 표기한다. 신청 가능한 항목을 가정했으며, 실제 도메인에 신청·마감 개념이 없다면 필드와 조건을 다시 정의한다.

| 프리셋 | 화면 이름 | 조건 | 정렬 | 최초 표시 개수 |
| --- | --- | --- | --- | --- |
| TODAY | 오늘 | 오늘 시작하며 현재 신청 가능한 공개 항목 | 시작 시각 오름차순, ID 오름차순 | 6 |
| CLOSING_SOON | 마감 임박 | 현재부터 24시간 이내 신청이 마감되는 신청 가능한 공개 항목 | 신청 마감 시각 오름차순, ID 오름차순 | 6 |

공통 규칙:

- 시간 기준은 서버의 현재 시각이며, 하루의 경계는 `Asia/Seoul` 기준이다.
- 신청 가능 조건은 `applicationOpensAt <= now < applicationClosesAt`이며, 신청을 받는 상태여야 한다. 정원 제한이 있는 도메인은 잔여 정원이 있는 조건도 적용한다.
- 비공개·삭제·취소 항목은 항상 제외한다. 공개 여부는 서버가 강제하며 요청으로 해제할 수 없다.
- TODAY는 시작 시각이 `[오늘 00:00, 내일 00:00)`에 포함되는 항목이다. 여러 날 진행되는 항목의 오늘 진행 여부는 이 기준에 포함하지 않는다.
- CLOSING_SOON은 신청 마감 시각이 `(now, now + 24시간]`인 항목이다. 마감 시각이 없으면 제외한다.
- 마감 시각과 현재 시각이 같으면 제외한다. 각 요청 안에서는 동일한 `now`를 사용한다.
- 두 영역에 같은 항목이 표시될 수 있다. 중복 제거를 위해 임의로 결과를 줄이거나 추가 조회하지 않는다.
- 날짜가 바뀌거나 화면에 재진입하면 다시 조회한다. 상시 자동 갱신 간격은 별도 합의한다.

## 3. C 탐색 API 제안

| 항목 | 명세 |
| --- | --- |
| Method | GET |
| Path | `/api/v1/items` — 실제 도메인명 확정 후 변경 |
| 인증 | 공개 목록 조회는 인증 없이 허용하는 안으로 제안 |
| 성공 | `200 OK`, `ApiResponse<ItemSearchResponse>` |
| 요청 본문 | 없음 |

### 요청 쿼리

| 이름 | 타입 | 기본값 | 허용값 및 의미 |
| --- | --- | --- | --- |
| `availableOnly` | boolean | `false` | `true`면 현재 신청 가능한 항목만 조회 |
| `startDate` | date | 없음 | 시작 일자의 하한, 포함. `yyyy-MM-dd`, 한국 시간 기준 |
| `endDate` | date | 없음 | 시작 일자의 상한, 포함. 서버에서는 다음 날 00:00 미만으로 변환 |
| `closingWithinHours` | integer | 없음 | 1~168. 마감 시각이 `(now, now + 값 시간]`인 항목 |
| `sort` | string | `START_ASC` | `START_ASC`, `CLOSING_ASC` |
| `page` | integer | `0` | 0 이상의 페이지 번호 |
| `size` | integer | `20` | 1~100 |

- 모든 필터는 AND로 결합한다. 날짜 경계는 각각 생략할 수 있으나 양쪽을 지정하면 `startDate <= endDate`여야 한다.
- `START_ASC`: `startsAt ASC, id ASC`.
- `CLOSING_ASC`: `applicationClosesAt ASC, id ASC`. 마감 시각이 없는 항목은 마지막에 두고 ID로 정렬한다.
- 필터링 → 정렬 → 페이지 처리 순서로 실행한다. 같은 조회 상태에서 동률 항목의 순서를 보장한다. 데이터 변경 중 페이지 간 중복 방지까지 보장하지는 않는다.
- 지원하지 않는 파라미터·정렬값이나 잘못된 타입·범위는 400으로 응답한다.

### 메인 프리셋 요청

2026-10-22 한국 날짜 기준 예시:

```http
GET /api/v1/items?availableOnly=true&startDate=2026-10-22&endDate=2026-10-22&sort=START_ASC&page=0&size=6
```

```http
GET /api/v1/items?availableOnly=true&closingWithinHours=24&sort=CLOSING_ASC&page=0&size=6
```

TODAY의 날짜는 호출할 때 `Asia/Seoul`로 계산한다. UTC 기준 `toISOString().slice(0, 10)`으로 만들지 않는다. 서버의 신청 가능 판단은 요청 날짜와 무관하게 서버 현재 시각을 따른다.

### 성공 응답 예시

UNNIE-121: 목록 항목은 아래 8개 필드를 반환하는 계약으로 확장한다. C 탐색 API의 실제 경로·시각 매핑·판매가 계산은 C 담당자와 확정해야 한다.

```json
{
  "success": true,
  "data": {
    "content": [
      {
        "id": 101,
        "title": "예시 항목",
        "startsAt": "2026-10-22T18:00:00+09:00",
        "applicationClosesAt": "2026-10-22T17:00:00+09:00",
        "shopName": "예시 뷰티샵",
        "price": 32500,
        "latitude": 37.4982,
        "longitude": 127.0276
      }
    ],
    "page": 0,
    "size": 6,
    "totalElements": 1,
    "totalPages": 1,
    "hasNext": false
  },
  "error": null,
  "timestamp": "2026-10-22T12:00:00+09:00"
}
```

8개 키를 모두 포함한다. `id`는 양의 안전한 정수, `title`과 `shopName`은 공백이 아닌 문자열이다. `startsAt`은 필수이며 날짜·시각은 오프셋을 포함한 ISO-8601로 반환한다. `applicationClosesAt`은 일반 탐색에서는 null을 허용하지만 위 두 메인 프리셋에서는 필터 조건에 따라 항상 존재한다.

| 필드 | 타입 | 의미 |
| --- | --- | --- |
| shopName | string | 매장명 |
| price | number | 서버가 계산한 원화 판매가. 0 이상의 안전한 정수이며 0원도 허용 |
| latitude | number 또는 null | 위도, -90~90 |
| longitude | number 또는 null | 경도, -180~180 |

좌표는 유효한 숫자 쌍 또는 두 필드 모두 null로 반환하는 안으로 정의한다. 미등록 좌표의 항목은 카드에는 표시하고 지도 마커에서는 제외하도록 프런트 담당자와 맞춘다. 가격과 좌표는 문자열 숫자나 샘플 값으로 보완하지 않고 서버 값을 사용한다. 실제 응답 검증 및 오류 처리는 C API·프런트 연결 구현에서 적용한다.

UNNIE-121의 변경 범위는 기존 문서의 응답 계약 확장이다. 새 프런트 파일을 추가하거나 현재 홈·탐색 화면을 수정하지 않는다. 실제 응답 DTO·조회 로직은 C API 담당자가, 카드·지도 연결은 메인 프런트 담당자가 구현한다. 이 문서의 예시는 현재 서버가 해당 응답을 반환한다는 의미가 아니다.

`totalElements`는 필터에 맞는 전체 개수, `totalPages`는 전체 페이지 수다. 결과가 없으면 `content: []`, `totalElements: 0`, `totalPages: 0`, `hasNext: false`로 200을 반환한다. 범위를 벗어난 페이지도 빈 목록을 반환하되 실제 전체 개수와 전체 페이지 수는 유지한다.

### 오류 응답

| HTTP | 상황 | 코드 |
| --- | --- | --- |
| 400 | 날짜 형식·범위 오류, 파라미터 타입·값 오류 | `SEARCH_001` (제안) |
| 500 | 예상하지 못한 서버 오류 | `COMMON_500` (컨벤션 예시, 공통 구현과 조율) |

```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "SEARCH_001",
    "message": "탐색 요청 파라미터가 올바르지 않습니다."
  },
  "timestamp": "2026-10-22T12:00:00+09:00"
}
```

오류 코드가 확정되면 C 구현의 `ErrorCode`와 `docs/api/error-codes.md`에 함께 등록한다. 이 문서만으로 공통 오류 코드를 확정하지 않는다.

## 4. A 프런트 연결 규칙

- 컨벤션의 `컴포넌트 → Zustand store 액션 → api 모듈 → axiosInstance` 경로로 호출한다.
- 프리셋은 상수 또는 생성 함수로 관리하며 날짜는 요청 시 계산한다.
- 두 영역은 각각 요청하고, 각 영역의 로딩·성공·빈 결과·실패 상태를 관리한다. 한 영역의 실패로 다른 영역의 성공 결과를 숨기지 않는다.
- 로딩 중에는 로딩 표시, 빈 결과에는 안내 문구, 실패에는 오류 안내와 재시도를 표시한다. 실패를 빈 결과로 표시하지 않는다.
- 더보기는 같은 프리셋 조건을 탐색 화면에 전달하고 첫 페이지부터 조회한다.
- 카드 클릭 이후 상세 화면에서 최신 신청 가능 여부를 확인한다. 목록 노출만으로 신청 가능 여부를 보장하지 않는다.
